## Architecture the cutover relies on

Two Cloudflare Workers on the zurielst.com zone, each with two configs:

| Worker | Routeless CI config | Cutover overlay (routes) |
| --- | --- | --- |
| zurielst-site (static assets) | workers/site/wrangler.jsonc | workers/site/wrangler.cutover.jsonc |
| zurielst-chat-api (POST /api/chat) | workers/chat-api/wrangler.jsonc | workers/chat-api/wrangler.cutover.jsonc |

- CI deploys the routeless config. .github/workflows/deploy.yml runs on every
  push to main behind the GitHub environment `deploy`, which has a required
  reviewer and holds the only two secrets, CLOUDFLARE_ACCOUNT_ID and
  CLOUDFLARE_API_TOKEN. As of main b071157 the workflow deploys the site
  worker only; the chat-api deploy step is not yet wired in (the header
  comment in deploy.yml defers it), so chat-api code deploys are manual for
  now, using the same routeless config.
- The overlay configs are identical in intent plus a `routes` list. Each was
  deployed once per phase by the operator locally under wrangler OAuth
  (`npx wrangler login`), because the CI token deliberately lacks route
  (zone) permissions. A wrangler deploy whose config has no `routes` key
  leaves existing routes untouched, so every later routeless CI deploy kept
  the routes attached. This was observed working: PRs #13, #14, #15, #16 and
  #23 all merged to main after the phase 1 overlay deploy on 2026-08-30 and
  none detached the production routes.
- Cloudflare picks the most specific matching route, so the exact pattern
  zurielst.com/api/chat wins over zurielst.com/* and API traffic reaches the
  chat worker while the site worker serves everything else.

## Rollback

- Site only: delete the zurielst.com/* route in the dashboard, or redeploy
  workers/site/wrangler.cutover.jsonc with that pattern removed. The apex
  immediately falls back to the GitHub Pages origin.
- Chat only: delete the zurielst.com/api/chat and
  staging.zurielst.com/api/chat routes the same way (dashboard, or redeploy
  the chat overlay minus the patterns).
- Full rollback additionally re-swaps the rate-limiting rule back to /ai/
  and re-attaches zurielst.com/ai* to zuriel-ai-resume-assistant.
- No DNS change is needed in any of these; the origin stays live underneath.

## Operational gotchas hit during the cutover

- Secrets set through a PowerShell pipeline gain a trailing CRLF that
  wrangler rejects at deploy time. Set them from bash with
  `printf %s "$VALUE" | gh secret set NAME ...` so no newline is appended.
- Read merge and test exit codes directly, never after a pipe: a pipeline's
  `$?` is the LAST stage's exit code, so `cmd | tee log` reports tee, not cmd.
- GitHub Actions `concurrency: deploy-production` serializes deploys. A run
  left waiting for environment approval blocks the whole queue behind it;
  approve or cancel promptly.
- Rerunning a superseded workflow run reuses the old merge snapshot, so a
  rerun deploys old code. Trigger a fresh run (new push or merge) instead.
- Local Windows vitest uses the pool's single-worker mode to keep concurrent
  workerd teardown races from changing the exit code. Linux deploy.yml keeps
  the default isolated runtimes and strict exit handling.
